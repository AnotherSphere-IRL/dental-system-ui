1. User Roles & Access PermissionsThe system serves a single clinic and enforces strict Role-Based Access Control (RBAC).   Clinic Doctor / Dentist (Admin/Clinical User):Access/View: Master calendar, all authorized patient records, imaging, financial reports, operations dashboard, and audit logs.   Create/Edit: Digital dental charts, medical alert reviews, service price lists, inventory thresholds, manual walk-in assignments, and user roles.   Approve/Reject: Supply purchase orders (POs), refund/fee adjustments, and patient reschedule requests (if overriding rules).   Retrieve: Can initiate Records Retrieval searches, requiring patient authorization if not previously assigned.   Authorized Clinic Personnel / Staff:Access/View: Daily schedule, patient demographic profiles, inventory counts, and overdue balance alerts.   Create/Edit: Expense entries (requires receipt upload), in-house X-ray uploads (clinic scenario), manual payment logging (in-clinic payments).   Retrieve: Can search basic patient records for scheduling but restricted from viewing clinical charts/PHI without explicit RBAC permission.   Patient (Authenticated End-User):Access/View: Personal dashboard, upcoming/past appointments, specific 4-tier reminders, due-today balances, and own imaging timeline.   Create/Edit: Self-registration (OTP/OAuth), self-service booking (with integrated reservation fee), digital intake forms, patient-portal X-ray uploads, self-reschedule/cancellation (governed by 7-day/2-day rules).   Authorize: Grants or denies data access requests from new dentists via the Records Retrieval workflow.   2. Information Architecture & NavigationThe UI must provide distinct navigation structures for the clinic side and the patient portal.Doctor / Clinic Staff Navigation:Dashboard: Aggregated view of today's appointments, due/overdue recall alerts, low-stock alerts, pending PO approvals, pending access requests, and daily income summary.   Calendar (Module 4): Master schedule, conflict management, walk-in assignment.   Patients: Global Records Retrieval search bar. Leads to Centralized Patient Profiles (Identity, Intake, Charts, X-rays).   Billing & Finance: Service Price List, Payment Processing, Expense Recording, Outstanding Balances, Refunds, and Financial Reports.   Inventory & Suppliers: Live stock list, Expiration monitoring, Auto-drafted PO review, Supplier directory.   Settings: User Management, RBAC, System Audit Logs.   Patient Portal Navigation:My Dashboard: Next appointment, outstanding due-today balance, recall notifications.   Appointments: Book new, reschedule/cancel (shows refund/forfeiture calculations), appointment history.   My Health Record: Pre-visit Intake forms, Upload External X-rays, Access Authorization requests (Grant/Deny UI).   Billing: Payment history, reservation fee receipts, balance payment portal.   3. Core Workflows & Screen SpecificationsA. Appointment Booking & Payment (Modules 1 & 4)User Action: Patient selects service and date.   System Response: Fetches real-time slots from master calendar (conflict-free).   User Action: Patient selects slot.System Response: Places temporary hold on slot; calculates reservation fee via Service Price List. UI displays integrated payment gateway prompt.   User Action: Patient completes payment.System Response: [Success State] Confirms booking, finalizes slot, triggers instant confirmation message, and schedules 4-tier reminder series (48h, 24h, 3h, 1h). [Error/Timeout State] Releases slot, notifies patient.   B. Digital Patient Intake & Medical Alerts (Module 7)User Action: Patient pre-fills validated digital medical history form (e.g., answers "Yes" to known allergies and diabetes).   System Response: Maps responses to profile ID. Analyzes responses via predefined text rules.   Output UI: Generates distinct Medical Alerts on the dentist’s dashboard. Crucial Design Rule: Display as rule-based text (e.g., "Medical Alert: Patient reported history of diabetes"), not as an AI diagnosis. Include a hyperlink directly to the patient's original intake response for clinical review.C. Digital Dental Charting (Module 9)User Action: Dentist examines patient and clicks a specific tooth on the Universal Tooth Numbering UI (e.g., Tooth #3).   System Response: Opens a tooth-specific clinical template.User Action: Dentist records condition (e.g., Caries), procedure (e.g., Composite restoration), clinical notes, and selects supplies used.   System Response: Auto-timestamps the entry, deducts supplies from live inventory, and routes financial data to billing.   Output UI: Updates the chronological Digital Dental Chart and generates a general "Dental Status" summary block (a factual compilation of documented missing/restored/treated teeth, not an automated diagnosis).D. X-Ray & Imaging Dual-Upload (Module 10)Scenario 1 (Clinic): Authorized staff clicks "Upload Imaging" on patient profile, selects sensor file/picker, system extracts metadata, compresses, and adds to centralized timeline.   Scenario 2 (Patient): Patient logs into portal, clicks "Upload External X-Ray", selects file.System Response: UI shows file validation loader. Upon success, auto-associates to the upcoming visit and indexes into the same centralized timeline for the dentist to review.   E. Records Retrieval & Access Authorization (Module 11)User Action: New dentist searches for a patient via the global search bar.   System Response: System detects lack of existing permission and displays a "Request Access" modal.User Action: Dentist clicks "Request Access."System Response: Pushes an instant SMS/Email/Portal notification to the patient. UI shows "Access Request Pending" state.User Action (Patient): Patient clicks "Grant Access" in their portal.Output UI (Dentist): Screen refreshes to "Access Granted." System retrieves permitted data points (identity, intake, charts, imaging) and logs the event in the immutable audit trail.   F. Inventory Automation & PO Approval (Modules 17-20)System Response: Charting module deducts a supply item. System detects stock is below the minimum threshold.   Output UI: Pushes a red Low-Stock Alert to the Operations Dashboard and auto-drafts a Purchase Order (PO).   User Action: Doctor clicks the pending PO alert.System Response: Displays the drafted PO (Item, Qty, Supplier).User Action: Doctor edits quantities if needed and clicks the mandatory "Approve" button.   System Response: Generates structured PDF, emails supplier via SMTP, and moves PO to "Submitted" status. Exception UI displays if the email bounces.   5. Essential UI States to DesignEmpty States: No upcoming appointments, no medical alerts, no pending POs, zero search results.Loading/Pending States: File upload validation, Access Request Pending (Records Retrieval), Payment Processing.Success States: Appointment Confirmed, Access Granted, PO Approved & Sent.Error/Warning States: Low-Stock Alert, Item Expiring Soon, Reschedule request rejected (< 7 days warning), Unauthorized Access Attempt.   Confirmation Modals: Patient cancelling appointment (must show fee forfeiture/refund calculations based on the 2-day rule).
